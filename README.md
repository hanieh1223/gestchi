# قسط‌یار (Gestchi)

رابط کاربری سامانه قسط‌یار با React و Vite. مخزن GitHub محل توسعه مرحله‌ای نسخه React است.

## راه‌اندازی محلی

نیازمند Node.js سازگار با نسخه Vite این پروژه.

```bash
npm install
npm run dev
```

## کنترل کیفیت

```bash
npm run lint
npm test
npm run build
npm run check
```

## معماری

- `src/app`: نقطه ورود، مرز خطا و تنظیمات سطح برنامه
- `src/features`: قابلیت‌های مستقل کسب‌وکار؛ هر قابلیت مالک UI، منطق دامنه و سرویس‌های خودش است
- `src/components/ui`: اجزای پایه و بدون وابستگی به دامنه
- `src/components/shared`: اجزای مشترک بین چند قابلیت
- `src/layouts`: چیدمان صفحات
- `src/services`: ارتباطات زیرساختی مانند API و ذخیره‌سازی
- `src/data`: داده‌های seed و نمونه
- `src/constants`: مسیرها و مقادیر ثابت
- `src/utils`: توابع عمومی و بدون وابستگی به React
- `src/styles`: design tokens، استایل پایه و استایل‌های برنامه

## اصول اجرایی

1. کامپوننت‌ها مسئول نمایش و تعامل UI هستند؛ قوانین مالی و تجاری در domain قرار می‌گیرند.
2. داده‌های نمایشی با داده‌های سرور مخلوط نمی‌شوند.
3. دسترسی به API فقط از لایه services انجام می‌شود.
4. دسترسی به localStorage فقط از آداپتور storage انجام می‌شود؛ داده حساس نباید در آن ذخیره شود.
5. محاسبات مالی باید با تست واحد پوشش داده شوند.
6. هیچ نتیجه اعتبارسنجی، تأیید بانکی یا پرداختی در محیط واقعی نباید با منطق سمت کاربر شبیه‌سازی یا قطعی اعلام شود.
7. قابلیت‌ها به‌صورت مستقل و مرحله‌ای مهاجرت می‌کنند؛ هر مرحله باید lint، test و build موفق داشته باشد.

## وضعیت مهاجرت از نسخه HTML

نسخه HTML اولیه یک نمونه تعاملی با داده‌های محلی مرورگر است. قابلیت‌های آن شامل فروشگاه و محصول، مقایسه و محاسبه طرح اقساط، سبد و checkout، سفارش و قرارداد، استعلام، داشبورد مشتری، پنل فروشنده، پنل مدیریت، نقش‌ها و گزارش فعالیت و سایت اختصاصی فروشگاه است.

در نسخه React فعلی، پوسته عمومی، صفحه خانه، کاتالوگ و فهرست فروشگاه‌ها پیاده‌سازی شده‌اند. منطق محاسبه اقساط از نسخه اولیه به ماژول دامنه مستقل منتقل و برای آن تست واحد نوشته شده است. مسیرهای دیگر فعلاً صفحات انتقال هستند و هنوز قابلیت عملیاتی ندارند.

داده‌های `src/data/demoData.js` فقط seed نمایشی هستند. احراز هویت، پرداخت، اعتبارسنجی بانکی/چک، ارسال پیامک و ذخیره سفارش واقعی بدون backend امن و سرویس‌های مورد تأیید قابل بهره‌برداری نیستند.

## ساختار دامنه‌های برنامه

- `features/catalog`: فهرست، فیلتر و جزئیات کالا
- `features/stores`: فروشگاه و شرایط اختصاصی فروش
- `features/installments`: محاسبه‌گر و قوانین طرح‌های اقساطی
- `features/cart` و `features/checkout`: سبد و فرایند سفارش
- `features/inquiries`: گردش کار استعلام و نتیجه آن
- `features/orders`: سفارش‌ها، قراردادها و پیگیری
- `features/auth`: ورود و احراز هویت
- `features/customer-dashboard`: اعتبار، تراکنش، پشتیبانی و اقساط
- `features/merchant`: مدیریت فروشگاه، کالاها، درخواست‌ها و قالب سایت
- `features/admin`: مدیریت سامانه، نقش‌ها و گزارش فعالیت

این پوشه‌ها به‌تدریج و هم‌زمان با انتقال واقعی هر قابلیت تکمیل می‌شوند؛ از ایجاد فایل‌های خالی و لایه‌های غیرضروری خودداری می‌کنیم.
